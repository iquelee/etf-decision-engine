## 2. 请求预算（`B-*`）

### B-01 联网模式必须显式给预算

- 联网运行时 `--max-requests` **必填**；未提供 ⇒ **拒绝运行**（`SystemExit`，**0 请求、0 写入**）。
- 理由：默认无上限等于默认允许无限重试。

### B-02 计划前置校验（**先于任何候选请求**）

- 运行开始前须计算计划：`planned = 枚举请求 + 日历请求 + 筛后候选数`。
- 若 `planned > max_requests` ⇒ **在任何候选请求之前**中止，`budget_sufficient = false`。
- 该闸门使用**逻辑请求数**，**不扣除缓存命中**（见 B-04 的口径差异说明）。

### B-03 运行时闸门必须先于请求发出

- 预算超限必须在**发出第 N+1 次真实请求之前**抛错中止（`RequestBudgetExceeded`），
  **不是**事后汇总计数。
- 理由：事后计数意味着超额请求**已经发出**。

### B-04 缓存命中不计入预算（口径差异，必读）

| 位置 | 计数对象 | 是否扣缓存 |
|---|---|---|
| B-02 **前置**闸门 | **逻辑**请求数 | **否** |
| B-03 **运行时**闸门 | **真实**请求数（`self.requests`） | **是**（命中不 +1） |

⚠ **由此产生一个反直觉但正确的现象**：全命中缓存时，`budget_remaining = max_requests`，
**不等于** `max_requests − planned_requests`。**断言与文档都不得混用这两个口径。**
（实证：run8 以 `--max-requests 41` 启动被前置闸门拒绝，因为逻辑计划为 44、余量 −3；
而该轮实际真实请求只有 **1** 次。）

### B-05 计划必须机械留痕

计划须以机器可读形式写入进度记录，至少包含：
`scope` / 快照来源文件与**双口径** SHA / `snapshot_count` / `selected_code_count` /
`calendar_requests` / `enumeration_requests` / `planned_requests` / `planned_formula` /
`max_requests` / `budget_remaining_after_plan` / `budget_sufficient` / `matches_stage_a_caliber`。

### B-06 三档请求口径（统一写法）

| 档 | 含义 |
|---|---|
| ① **逻辑 URL 数** | 计划要访问多少个**不同**的 URL |
| ② **每 URL 最多尝试次数** | 单个逻辑 URL 的最坏尝试上限 |
| ③ **最坏 HTTP 请求数 = ① × ②** | 必须用乘法给出，并给出加固前后的变化 |

⛔ **主机轮换不是乘数**：它只是「每次尝试选哪台主机」的**选址逻辑**（换台主机重试**同一个**逻辑 URL），
不产生额外请求 ⇒ **不得再乘主机台数**。
（统一写法示例：旧设计最坏 **61 个逻辑 URL × 每 URL 最多 8 次 = 488 次**；加固后 = **44 次**。）

### B-07 预算授权须单独立项

**代码包合并 ≠ 取数授权。** 即使预算逻辑已合入 `master`，任何一次真实联网取数
**仍须单独申请、单独记账**（含次数上限与失败后的处置）。

### B-08 显式人工联网确认开关 —— **已否决提案（`V-05` 最终裁决：不新增）**

- **`V-05` 最终裁决：不新增显式 `NETWORK_AUTHORIZED` 联网确认开关。**
- ⛔ 本行仅作**被否决提案的历史记录**保留；「增加开关」「默认恒为 `false`」等表述**均不构成有效要求**。
- ⛔ **不得影响现有 `B-01` / `--max-requests` 或其他准入门禁** —— 准入门禁维持现状，一字不改。
- **现行口径（继续有效）**：代码合并 / 部署 / 测试通过 / 脚本存在，**均不得自动等价为联网授权**（见 `B-07`）。

## 3. 稳定缓存（`C-*`）

| 编号 | 要求 |
|---|---|
| C-01 | 默认缓存根必须**移出** `%TEMP%` 与 `~/.cache`（这些位置会被系统清理，导致证据不可复核） |
| C-02 | 解析出的缓存路径若落在**仓库内** ⇒ **fail-closed 拒绝**（`raise SystemExit`），避免把大体积原始数据写进版本库 |
| C-03 | 缓存键必须**纯确定性**：只依赖请求 URL（现行口径 `sha256(原始 URL)[:16].json`），不得含时间戳 / 本机路径 / 随机数 |
| C-04 | 命中即复用，**不重复请求**，且**不消耗预算**（B-04） |
| C-05 | **禁止原地覆盖**既有缓存或既有数据版本；新口径须声明新 `data_version` |
| C-06 | 缓存必须可被第三方**独立复算**：键可由 URL 机械重建，且每份 payload 有指纹（§4） |

## 4. 哈希（`H-*`）

| 编号 | 要求 |
|---|---|
| H-01 | 任何文档引用 sha256 **必须声明口径**：raw 字节 vs **项目口径**（`sha256(utf8 解码 + CRLF→LF 归一化)`） |
| H-02 | 引用 `bundle_sha256` / `lock_sha256` / `ROOT_ANCHORS` 时，一律按**项目口径**并注明来源常量 |
| H-03 | payload 指纹（`payload_sha256`）**只在 `generated_on` 当日有效**；来源复权基准漂移会使同一 URL 在不同抓取日产生不同字节 |
| H-04 | 跨抓取日引用同一 `payload_sha256` **即为无效引用**，不得据此声称「数据未变」 |

## 5. 进度与失败记录（`P-*`）

| 编号 | 要求 |
|---|---|
| P-01 | 逐行 **JSONL + 立即 flush**（崩溃时已写入的行必须可读） |
| P-02 | 每个数据行至少含：`code`（日历请求为 `null`）· `source`（`network` / `cache`）· `attempts` · `http_status` · `bytes` · `payload_sha256` · `generated_on` · `ts` · `error` |
| P-03 | **末行 summary** 至少含：`requests_network` · `cache_hits` · `failures` · `aborted` · `max_requests` · `scope` · `request_plan` · `consecutive_failures_is_fatal` · `type = "summary"` |
| P-04 | **不覆盖**历史进度：每次运行写**新文件**（命名带 run 序号或时间戳） |
| P-05 | **失败必须留痕**（freeze §7）：不得静默删除、不得用「无记录」表达「没发生」 |
| P-06 | 失败时的**输出处理**：不写 `--out`，避免产出「全是 `data_error` 却像完整 artifact」的半成品 |
| P-07 | 若某次操作**因前置闸门拒绝运行**（如 B-01 / B-02）⇒ 不会有进度文件。此种「**无留痕**」必须在该轮的操作记录中**显式说明**，不得与「运行过但无输出」混淆 |
| P-08 | **已否决提案（历史说明，非有效要求）：** 曾有提案主张建立机器可读的「拒绝事件」台账（append-only 事件记录，含 `timestamp` · `operation` · `target` · `gate` · `rejection_reason` · `authorization state` · `request_sent: false` · `network_effect: false` 等字段）。**`V-04` 最终裁决：不新增独立拒绝事件台账。** ⛔ 上述 8 字段强制结构与 append-only 义务**均不成立**，**不得呈现为有效要求**；本行仅作**被否决提案的历史记录**保留。 |

## 6. 双模式边界（**本草案的核心新增内容**）

> ⚠ **现状**：当前代码**只有** §6.1 一种模式。§6.2 **`V-01` = 暂不立项**（2026-09-17 立项口径已废止）
> —— 本节仅保留诊断模式的**候选框架**，**不批准工程实现**，也**不授权** `WP-G2-09` / 本地原型 / 联网 / 取数。
> 实现属**独立加固包**（独立授权 / 独立测试 / 独立代码评审），不得与 WP-G2-08 文档裁决混成一个提交。
> ⛔ **默认 `ADMISSION`（准入）路径的「前置拒绝即零写入」必须保持**；**诊断记录不得被准入路径读取**。
> 提出它的动机见 `gen2_data_access_incident_20260917.md` §6（`510170` 死锁：任何续跑的第 1 个真实请求
> 都是同一个会失败的标的 ⇒ fail-fast 下收益恒为 0）。

### 6.1 准入模式（`ADMISSION`）—— 现行唯一合法模式

**行为**（本草案不修改，只固化）：

- **fail-fast**：单个 URL **只尝试 1 次**；失败立即**整体中止**；**不换主机、不自动重试、无退避**。
- 实现常量可被测试断言（`ATTEMPTS_PER_URL = 1`、`HOST_ROTATION = False`）。
- **不写 `--out`**（P-06）。
- 联网时 `--max-requests` 必填（B-01），运行时闸门先于请求（B-03）。

**可用性**：其产物**可以**用于准入判定（逐标的准入、段级充分性核验等）。

### 6.2 诊断采集模式（`DIAGNOSTIC`）—— **`V-01` = 暂不立项；本轮尚未实现，且未获任何授权**

> ⛔ **`V-01` = 暂不立项；不构成诊断模式实现、联网取数或 `WP-G2-09` 的授权。**
> 本节仅保留诊断模式的**候选框架**，**不批准工程实现**：
> - **不授权** `WP-G2-09`、本地原型、联网或取数；
> - **不授权**任何诊断运行的执行（含 `D-1` 的 CLI 开关开启）；
> - ⛔ **默认 `ADMISSION` 路径的「前置拒绝即零写入」必须保持**；
> - ⛔ **诊断记录不得被准入路径读取**（`V-03` / `X-1`：**条件式**——须未来 `V-01` 立项 + 独立实现授权后方生效；当前不构成实现或测试授权）。
> 若未来要转为「立项」，须由人工**另行明确授权**；即便如此，其**工程实现**仍属**独立加固包**
> （独立授权 · 独立测试 · 独立代码评审），⛔ **不得静默修改现有正式 `fail-fast` 语义**。

**动机**：把「搞清楚为什么失败」与「取得准入数据」**解耦**。当前二者被绑在同一条 fail-fast 路径上，
导致**任何一次诊断都会消耗一次准入预算，且无法推进准入**。

**允许的行为**（仅在显式开启该模式时）：

- 遇失败**跳过**该标的并继续（不整体中止）；
- 对被跳过的标的写 **`degraded` 标记**与失败原因。

**强制约束（九条，缺一不可；`D-9` 为 `V-02` Human Ruling 回填）**：

| # | 约束 |
|---|---|
| D-1 | 必须是**独立的 CLI 开关**，默认**关闭**；开启本身需要**一次显式授权** |
| D-2 | 必须使用**独立命名空间**：独立缓存根 + 独立进度文件前缀 + 独立 run 标识，**不得**与准入缓存/进度混放 |
| D-3 | 产物必须带**不可撤销**的 `non_admissible = true` 标记（进度行 + 摘要行 + 任何输出文件） |
| D-4 | **不得**写入任何准入用途的 `--out`；即使写了，也须以 `non_admissible` 前缀命名并禁止被准入流程读取 |
| D-5 | **不得**作为 freeze §2.6 段级充分性的证据（缺一个标的仍是缺一个标的，跳过不等于满足） |
| D-6 | **不得**作为「来源可用性」「失败归因」「限流」类结论的证据（跳过式采集**天然**无法区分「标的问题」与「链路问题」） |
| D-7 | **不得**与准入产物进入同一 manifest / 同一报告表格；若必须并列展示，须以**分栏 + 标记**形式呈现 |
| D-8 | 每次运行须**单独记账**（请求数、失败数、跳过数），并计入对目标主机的累计请求台账 |
| D-9 | **请求上限与授权粒度（`V-02` · 未生效候选口径）**：**当前不定执行预算**，下列数值**不得作为现行规则**；仅在未来 `V-01` 经人工明确立项后方可重新裁定 —— ① 每个被明确授权的标的最多 1 次请求（`1 symbol = max 1 request`）；② 0 次自动重试；③ 单次运行最大请求数 = 本次人工明确授权的标的数量；④ 授权粒度 = 每次诊断运行一次授权。⛔ 不人为创造固定「10 次 / 20 次」魔法数字。⛔ 该限定**仅作用于诊断模式**；**准入模式的 `B-01` / `--max-requests` / fail-closed 预算机制不受影响**。 |

**实现路径的红线**：

- ⛔ **不得**通过修改准入路径的常量（`ATTEMPTS_PER_URL` / `HOST_ROTATION`）来实现诊断模式；
- ✅ 必须**新增独立代码路径**，并在测试中**钉住**「准入路径的常量与行为**不变**」
  （即：加了诊断模式之后，准入模式的 fail-fast 回归必须仍然全绿）；
- ⛔ 诊断模式**不得**引入重试循环、退避、主机轮换 —— 跳过 ≠ 重试。单 URL 仍只尝试 1 次。
