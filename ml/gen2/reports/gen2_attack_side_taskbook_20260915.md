## 1. 为什么必须新立项，而不是「继续调 V2.0.1」

B3 的结论是**否证**：Rule V2.0.1 的经济门禁未通过。三条读数把它钉死为「机制问题」而非
「调参问题」：

| 事实 | 读数 | 排除了什么 |
|---|---|---|
| 零成本仍输 | defended **+57.16%** vs Main5 **+251.18%**（0 bps） | **排除**「费用/换手是根因」——换手 133.4 vs 11.5 只是放大器 |
| 多头年份全输 | 2023 **−49.30pct**、2025 **−43.89pct**、2024 −28.31pct、2026 −26.18pct | 指向**选池 / 仓位机会成本** |
| 防守腿有效 | MDD **−23.35%** vs −34.57%（+11.22pct）、2022 逆市年 **+24.43pct** | **防守端不是问题**；问题只在**进攻端** |

因此本任务书的**唯一目标**是：把「进攻端失效」从一个**结论**，拆成一组建模上可证伪、
且**能被新数据独立检验**的**机制假设**。

> ⚠️ **两条不可越界**：
> 1. **不得**据 B3 结果回调 V2.0.1 的任何参数后重跑。V2.0.1 保持冻结，作为**失败审计基线**。
> 2. **不得**用**任何已被观察的段**（含 B3 OOS 与 `2020` 段）来形成或选择新假设的任何阈值。

## 2. 三层证据模型（本轮裁决的核心结构）

三个层级的**证据力不同**，混用是这类研究最常见的失误。本任务书把三者**物理分开**：

```text
        ┌───────────────────────────────────────────────────────────────┐
 Stage M │  POSTMORTEM（事后归因）                                        │
        │  数据：2021-01-04→2026-09-04（B3 OOS）                          │
        │      + 2020-03-10→2020-12-31 + 2018-04-03→2020-03-06           │
        │  用途：只读归因、形成机制假设          ← 已观察，禁止拟合任何阈值 │
        │  证据力：0（不可作资格证据）                                     │
        └───────────────────────────────────────────────────────────────┘
        ┌───────────────────────────────────────────────────────────────┐
 Stage R │  RESEARCH（研究宇宙）                                          │
        │  数据：O2 新增的「更早上市、可交易 ETF」研究宇宙                 │
        │  用途：Dev 形成 / Val 一次性验证 → 定型结构性假设                │
        │  证据力：中（可支持「机制成立」，不可支持「生产资格」）           │
        └───────────────────────────────────────────────────────────────┘
        ┌───────────────────────────────────────────────────────────────┐
 Stage Q │  QUALIFICATION（前瞻资格）                                     │
        │  数据：当前 31 只池的**未来新增**交易日（O1 前瞻）               │
        │  用途：唯一的生产资格判定                                       │
        │  证据力：**高 —— 唯一**                                        │
        └───────────────────────────────────────────────────────────────┘
```

### 2.1 三层之间的**禁止流动**

| 方向 | 是否允许 | 说明 |
|---|---|---|
| M → 形成假设 | ✅ 允许 | B3 的失败归因只能走到「提出假设」这一步 |
| M → 定阈值 / 选参数 | ❌ **禁止** | 该段已被观察，任何在其上做选择都等于自欺 |
| R → 机制结论 | ✅ 允许 | 「在未观察数据上机制成立」 |
| R → **生产资格** | ❌ **禁止** | 研究宇宙与生产池不同（标的、成本、流动性结构都不同） |
| Q → 生产资格 | ✅ **唯一** | 前瞻、无偏、时间自然保护 |

> **一句话**：**R 层证明「想对了」，Q 层才能证明「能用」。** M 层只能证明「原来为什么不行」。

### 2.2 为什么需要 O2（而不是直接用 O1）

O1 只能等未来（约 **21 日/月**），且**不能用于参数搜索**。若研究完全依赖 O1，则「形成假设」
这一步将失去统计基础。O2 的作用是**为「形成结构性假设」提供一段尚未被观察的历史**，
从而让 O1 阶段的假设是**有依据的**、而不是拍脑袋的。

## 3. 数据边界：实测结论（M1 前置）

### 3.1 实测边界

来源：`ml/gen2/manifests/GEN2_B3_FROZEN_OOS_MANIFEST_20260915.json`（`input_data.files` /
`full_window`），只读核对。

| 事实 | 读数 |
|---|---|
| 日线池 | `deliverables/etf_daily_ml_pool/`，**31 只**，`rows_total = 38083`，`date_range = 2011-12-09 → 2026-09-04` |
| **逐标的起点差异极大** | `first ≤ 2018-04-03`：**2/31**｜`≤2019-01-01`：3/31｜`≤2020-03-10`：**9/31**｜`≤2022-01-01`：17/31｜`≤2024-01-01`：19/31｜**31 只全部有数据 = `2024-04-16`** |
| 规则信号窗（非 benchmark 约束） | `gen2_v2_defended` = `2018-04-03 → 2026-09-04`（2046 日）；`market_510300` = `2018-01-02`（2106 日） |
| **实际使用的公共窗** | `2020-03-10 → 2026-09-04`（**1577 日**）—— 由 **`main5_equal_weight`** 卡住，`excluded_leading_days = 2003` |

> ⚠️ **校正一处早期表述**：`2020-03-10` **不是**「31 只标的全部有数据的最早日期」（那实际是
> `2024-04-16`），而是**被 `main5` 基准卡住后的公共窗起点**。

### 3.2 ⚠️ 关键校正：那 10 只「640 根」是**数据源截断**，不是上市日限制

`ml/gen2/universe/universe_v1.json` 的 `data_note` 逐字记载：

> 「16 只新增 ETF 由腾讯 fqkline 抓取；其中 **10 只老 ETF**（医药/酒/消费/红利/银行/券商/有色/煤炭/纳指/标普）
> **仅 640 根约 2.5 年历史，长历史待东财源补**。」

实测与之一致：`512010 / 512690 / 159928 / 510880 / 512800 / 512000 / 512400 / 515220 / 159941 / 513500`
这 **10 只全部为 640 行、起点全部是 `2024-01-15`**（`159570` 635 行起点 `2024-01-22` 是次一例）。

**这条事实改变了 O2 的性质**：

- 这 10 只被 `universe_v1` 明确称为「**老 ETF**」，其**真实上市日远早于 2024-01-15**；
  本地 CSV 短，是**抓取长度上限**造成的，**不是标的没上市**。
- ⇒ **补历史 = 换/增加数据源（东财 `fqt=1` 全历史前复权）**，属于**取数工作**，
  **不需要虚构数据、不需要引入不可交易资产**。
- ⇒ 这 10 只是 **O2 的首选取数对象**：**早已上市、实际可交易、且其早期段此前从未进入任何
  Gen-2 运行**（未观察）。
- ⚠️ **须逐只核验**：真实上市日、首日成交额、停牌缺口、复权可用起点 —— **本文件不预设这些数值**，
  由 `gen2_data_boundary_freeze_20260915.md` §6 的审计模板逐只留档。

**边界（不可据此扩张）**：`159582`（`2024-04-16`）、`159570`（`2024-01-22`）、`513310`（`2022-12-22`）、
`518880`（`2023-05-09`）等**确实是近年上市**，其更早历史**不可得**。ETF 上市日对**这些**标的是硬下限。

## 4. O2 取数方案（Stage R）

### 4.1 首选：更早上市、实际可交易的 ETF

**对象（按优先级）**：

1. **`universe_v1` 的 10 只老 ETF 全历史**（`data_note` 已指明「长历史待东财源补」）——
   同一标的、同一 sector/cluster 语义、**无需改变宇宙结构**，是代价最低的一步；
2. 在上述基础上，**新增一批此前未纳入、更早上市且可交易**的 A 股场内 ETF，
   使研究宇宙在 `sector / cluster / asset_class` 覆盖上与现有池**同构**（否则跨宇宙不可比）。

**硬性要求**（详见 freeze 文档 §2 / §3）：

- **实际可交易**：交易所挂牌、有连续成交额、无长期停牌；
- **上市日 ≤ 目标 Development 起点 − 暖机期**（暖机期长度 **待 M1 裁决**，见 freeze §2.3）；
- **复权口径可比**：**同一标的整段单一数据源重取**，禁止跨源拼接未校准的序列（freeze §3.2）；
- **纳入规则在看到任何收益之前冻结**（pre-registration）。

### 4.2 次选：指数回溯 —— **仅可作机制参考**

用指数（如中证/国证系列指数）回溯更早历史，**只允许用于**：

- 观察「某机制在更早的市场结构下是否存在」——即**机制否证**；
- **不得**作为生产资格证据，**不得**据此宣称经济资格。

理由：指数**不可直接交易**（申赎/折溢价/跟踪误差/流动性均不同）⇒ 换数据域会引入
**不可交易性偏差**，其收益不可外推为可实现的组合收益。

### 4.3 O3 与 O4 的处置

- **O3（扩横截面）**：**仅作跨资产机制否证**。验证集换成当前 5 只之外的其他 ETF / 市场，
  不吃时间维度；**不作生产资格证据**。
- **O4（纯结构性少参数假设）**：**取消**。理由：其 Development 只能落在 `2020` 段（205 日，
  已被观察）⇒ 与裁决 #3 直接冲突，**不具备可用的验证基础**。

## 5. M2 归因诊断 —— 限定为 `POSTMORTEM_NOT_FOR_CALIBRATION`

**放行**（裁决 #6），但**严格限定**如下。每个产物、每张图、每个数字都必须携带
`POSTMORTEM_NOT_FOR_CALIBRATION` 标记。

### 5.1 允许：四层只读归因

| 层 | 观测 | 要回答的问题 |
|---|---|---|
| **① 选池** | `defended − main5` 的日频差做 Brinson 式分解（选池 / 权重 / 择时按 sleeve 归属）；逐年「选中组 vs 未选中组」的后续 20 日收益 | 差距来自「选了谁」还是「怎么配」？多头年份是否**系统性选反**？ |
| **② 权重·上限** | 科技 65% 上限 / cluster 上限 / 单只上限的**触发天数**与被截断权重；被截断部分的后续收益 | 上限在多头年份是否**截掉**了主要收益来源？ |
| **③ 防守** | 防守腿触发的天数与当日 / 后续 N 日机会成本；逐年分布 | 防守腿在**多头年份**是否被误触发？（注意 2022 是唯一亮点，不可一刀切） |
| **④ 换手·成本** | 换手拆为「调仓频率 × 单次调仓幅度」；0/5/10/20 bps 四档对照 | 换手是**结构性**还是**噪声性**？ |

### 5.2 禁止（硬边界）

- ❌ **参数搜索 / 网格 / 敏感性扫描**；
- ❌ **阈值调整**（含「顺手试一下 0.25/0.35」这类）；
- ❌ **新 `bundle_version` / 新 lock**；
- ❌ **为寻找通过结果而重跑任何 OOS**；
- ❌ 把归因结论写成「因此应把 X 调成 Y」——只允许写成「机制陈述 + 可证伪判据」。

### 5.3 输出边界

- M2 的产物**只能**形成：① 机制假设（含可证伪判据与所需数据段）；② 对本文档的修订建议。

## 7. 停止条件（应当直接终止，而不是继续调）

- 归因诊断无法给出**任何**在多头年份方向一致的机制 ⇒ 问题可能在**标的池本身**，
  应回到数据/标的层面立项，而不是继续改规则。
- 某假设的判据在 Development 段就无法满足 ⇒ 该机制不成立，登记为**否证**。
- 需要引入**新增参数**超过 2 个才能达到目标 ⇒ 判定为过拟合风险过高。
- 任何一步的验证必须依赖**已观察段**（§3.3）才能成立 ⇒ **不成立**。
- **更早的独立数据取不到**（或口径不可比 / 审计不通过），且不接受 O1 的时间成本 ⇒
  **停在文档层**（保留本任务书与 freeze 文档，不进入 M4）。
  这是一条**允许的落点**，不是失败。
