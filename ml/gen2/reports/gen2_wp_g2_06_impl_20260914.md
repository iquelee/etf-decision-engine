## 2. F4 缺陷与修复口径

**缺陷**（修复前的 `ml/gen2/portfolio/portfolio_builder.py`）：

```python
out["priority"] = out["rank"].astype(int)          # B2：legacy leadership rank
out.loc[out["role"] == "CORE", "target_weight"] = ...rdiv(1.0)   # B1：1/n 等权
```

丢弃了 `rule_v2_ab.build_v2_roles` 已算好的权威权重（单只 0.25 / cluster 0.40 / 广义科技 0.65），
且组合无现金腿、无防守腿 → 研究基线（归因 / 敏感性 / rotation）与权威路径不同口径，经济指标不可比。

**修复**：`build_portfolio_candidates` 改为**唯一构建口径**：

| 边界 | 实现要点 |
|---|---|
| B1 上限保留 | 权重**直接沿用**角色层 `target_weight`；只做上限**复核**（越界抛 `PortfolioBuildError`，绝不静默缩、绝不重置为等权） |
| B2 priority 来源 | `priority` 必填（`{date: {code: score}}`）；缺 → 抛错；**源码中不再出现 `rank`** |
| B3 现金/防守腿 | 现金腿 = `1 - Σ其他腿`（逐日，residual）；`apply_defense=True` 时套 regime 防守产生 hedge 腿 |
| B4 同口径 | 不重算权重（静态守卫：源码无 `1.0 / len` / `rdiv(1.0)`） |
| B5 priority 完备性 | 全覆盖 + 有限值校验；dense rank 按 **score 降序 → 同分 `code` 升序**（与输入行序无关）；`priority_source` / `priority_score` / `priority_hash` 落表 |
| B6 账本与归属 | `ledger_signals()` 剔除现金腿（账本内部按 `1-Σ证券` 算现金，避免重复计数）；`build_research_ledger()` 追加 `defense_weight` + `sleeve='GEN2_CANDIDATE'`；运行时断言**不存在** `final_target` |
| B7 跨端逐日对表 | 新增 `G2S-10`（`portfolio_build`）—— 双端跑同一面板，逐日比对权重 / 权重和 / 上限 / priority / score-config hash / sleeve |

新增公开面（`gen2.portfolio.portfolio_builder`）：
`PortfolioBuildError` · `priority_from_roles` · `priority_hash` · `portfolio_config_hash` ·
`ledger_signals` · `build_research_ledger` · `SLEEVE` / `CASH_CODE` / `PRIORITY_SOURCE`。

## 3. G2S-10（B7）设计 —— 对表不只比「有无腿」

`handler: portfolio_build`，`tier: STRUCTURED_SEAM`，2 case（`undefended` / `regime_path`）× 2 交易日。

**避免自证的夹具设计**：

1. 权威权重非等权 `0.20 / 0.20 / 0.25`：等权 `1/3 ≈ 0.3333` 与任何腿都不同 → 等权重置必被抓；
2. **分数最高的是 159582（不是权重最高的 159570）**：`priority.159582 == 1` 而 `priority.159570 == 3`
   → 「仍读 legacy rank / 按权重排序」必被抓；
3. 夹具 **不含 `rank` 列** → priority 只可能来自注入 score；
4. 两日 regime 不同（第 1 日 NORMAL 低波动 → scale 1.0；第 2 日 RISK_OFF → scale 0.35 + hedge 0.15）
   → 必须真的**逐日**对表，单日比对无法通过。

**对表字段**（`days.<date>.{weights.<code>, cash_weight, defense_weight, weight_sum, priority}` +
`max_single_seen` / `max_cluster_seen` / `max_tech_seen` / `sleeve` / `final_target_present` /
`priority_hash` / `config_hash` / `priority_source_all_injected`）。

**确定性保证**（两端位级一致）：权重求和累加顺序固定 `code` 升序；数值以 `toFixed(10)` / `:.10f`
字符串比较；`priority_hash` / `config_hash` 使用同一配方（`~` 分隔 + 字典序 + `|` 连接 + sha256）。
