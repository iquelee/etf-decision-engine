## §1 方法：为什么这样分解

V2.0.1 的失败判据是 **C1：累计净收益 > Main5**。直接对着一个数字说「输」无法定位原因，
因为从「Main5 等权」到「Gen-2 防守」之间**同时发生了五件事**。本包把它们**串成一条链**，逐步替换一个因素、
其余全部保持不变，从而得到每一步的独立贡献：

```
A  main5_equal_weight        Main5 PIT 等权（基线）
 │  ── 选池范围 ──
B  universe_equal_weight     全池等权（30 只 eligible）
 │  ── 角色选池 ──
C  core_equal_weight         每日 CORE 等权、**无任何上限**（本脚本合成的**诊断用**组合）
 │  ── 权重·上限 ──
D  gen2_v2_undefended        实际权威权重（单只0.25 / cluster0.40 / 科技0.65 + 残差现金）
 │  ── 防守 ──
E  gen2_v2_defended          防守后（risk-off 缩仓 + 黄金对冲 + 波动目标）
 │  ── 换手·成本 ──
F  E @10bps                  主判据成本档
```

**为什么必须插入 C**：若不插入 C，则「角色选池」与「权重/上限」会被**挤在同一步**里，
无法判断差距来自「选错了标的」还是「选对了但配错了权重」。C 因此是纯**诊断锚点**——
它**不是**新规则、**不是**候选参数、**不会**进入任何 bundle。

**分解的可加性**：各步 Δ 定义在同一基准（`0bps`）上，除最后一步 `E→F` 跨到 `10bps`，因此
`A→F = A→B + B→C + C→D + D→E + E→F` 是**严格 telescoping**，读数和必须闭合（见 §3.1 校验）。

**口径的硬约束**（全部沿用既有唯一权威，未新定义任何指标）：
* 角色语义：`gen2.baseline.rule_v2_ab.build_v2_roles`（V2 唯一权威状态机）
* 候选组合：`gen2.portfolio.portfolio_builder.build_portfolio_candidates`
* 账本：`gen2.backtest.ledger.run_ledger`（`execution_lag = 1`，T+1；`turnover = one_way_stock_legs`；**现金腿不计费**）
* 评估窗口：`common_evaluation_calendar`（各策略信号日 ∩ 收益日**交集**）
* 成本档：`0 / 5 / 10 / 20 bps`，**主判据 10 bps**，分解明细取 `0bps`（剔除成本以看机制）

## §3 四层加性分解（核心结论）

### 3.1 分解表（OOS 累计，基准 `0bps`）

| 步 | 层 | Δ（百分点） | 读法 |
|---|---|---|---|
| `A→B` | **选池范围**（Main5 等权 → 全池等权） | **−220.58** | ← **压倒性主因** |
| `B→C` | **角色选池**（全池等权 → 每日 CORE 等权，无上限） | **+15.44** | 规则**加分** |
| `C→D` | **权重·上限**（CORE 等权 → 实际权重，含 0.25/0.40/0.65 + 残差现金） | **−6.82** | 上限层**减分** |

### 3.3 三条硬结论

**① 失败的主因是「选池范围」，不是「规则」。**
`−220.58pp` 全部产生在 `Main5 等权 → 全池等权` 这一步 —— 也就是说，
**只要把评估基准从 Main5 换成 Gen-2 自己那个 30 只全池，V2.0.1 立刻不再落后**：
- `@0bps`：全池等权 `+30.60%` → Gen-2 防守 `+57.16%` ⇒ **规则层净增 +26.56pp**
- `@10bps`（**主判据档**）：全池等权 `+28.54%` → Gen-2 防守 `+37.54%` ⇒ **规则层净增 +9.00pp**
- 其中**增量来源可分离**：角色选池 `+15.44` · 防守 `+17.94`；**减量来源**：权重·上限 `−6.82` · 换手·成本 `−19.62`

**② 上限层（`C→D` `−6.82pp`）与成本层（`E→F` `−19.62pp`）是规则内部最大的两个减项。**
- 成本层 `−19.62pp` 对应：`gen2_v2_defended` 总换手 **133.42**（≈5.7 年 ⇒ 年均约 23.4 次单边），
  而 `main5_equal_weight` 仅 **11.53**（≈年均 2.0 次）—— **换手相差 11.6 倍**。
- 上限层的 `−6.82pp` 需要谨慎读：本步**同时**包含了
  （i）**单只 0.25 截断**（`|CORE| ∈ {1,2,3,4}` 时 `1/|CORE| > 0.25`）与由此产生的**残差现金**、
  （ii）**cluster 0.40 / 科技 0.65 缩权**。
  两个子效应在本包**未被分开**（见 §6-M3）。

**③ 防守层是**（在 OOS 上）**确实有效的**，且是唯一一个「既提收益又降回撤」的层：
`+17.94pp` 收益增量，同时 MDD 从 `−27.70%` 改善到 `−21.50%`（`@10bps` 为 `−28.96% → −23.35%`）。
但它的贡献**高度集中在 2025–2026**（见 §5），这一 regime 依赖性是 H5 的来源。

### 3.4 「选池范围」为什么这么大：一个必要的背景读数

同一个 OOS 窗口（`2021-01-04 → 2026-09-04`）：

| 组合 | 累计@0bps | 性质 |
|---|---|---|
| `main5_equal_weight` | **+251.18%** | 5 只**已存续**标的的 PIT 等权（含 3 只科技 + 黄金） |
| `market_510300` | **−3.75%** | 沪深300 单只持有 |
| `universe_equal_weight` | +30.60% | 30 只全池等权 |

即：**同一窗口内宽基约 `−3.75%`，而 Main5 为 `+251.18%`。**
这说明 **C1 判据的基准（Main5）本身是一个「在 OOS 期极度集中的赢家篮」**，
规则要「跑赢它」等价于要**在事后已知赢的 5 只标的上再加杠杆**级的表现。
→ 这是 **H1**（基准选择偏差）的来源，且**只能**在 O2 未观察段上验证。**本包不据此调整任何判据。**

## §4 机制层：上限绑定与 CORE 结构（**这是最刺眼的读数**）

### 4.1 上限绑定的真实口径（**已修正一处诊断缺陷**）

本包首版诊断误把候选面板的 **`CASH` 腿**（权重 = `1 − Σ证券`，均值≈0.50）纳入了统计，
因其 `0.50 ≥ 0.25` 而**假触发单只上限**，把「单只绑定天数」抬成虚高、并把残差现金恒压为 `0.0`。
已按 `portfolio_builder._assert_caps` 的**真实口径**重写（该函数在**追加现金腿之前**被调用）：

| 约束 | 真实口径 |
|---|---|
| 单只上限 `0.25` | 全部**证券行**的 `max`（**剔除 `CASH` 腿**） |
| cluster 上限 `0.40` | **仅 `role == "CORE"` 行**，按 `correlation_cluster` 分组求和 |
| 科技上限 `0.65` | **仅 `CORE` 行**且 cluster ∈ `tech_clusters`（`tech_hardware` + `software_ai`），按日求和 |
| 剩余现金 | `1 − Σ证券行` |

**修正后的自证**：候选面板「证券行残差现金（OOS）」= **`0.4992`**，
与账本实际读数 `gen2_v2_undefended.avg_cash_weight` = **`0.4991`** **四位一致** ⇒ 诊断与规则同口径。

### 4.3 机制链条（读源码得到，非推断）

`rule_v2_ab.build_v2_roles` 的权重赋值顺序：

```
roles["target_weight"] = 0.0                       # ← 全部角色先归零
core["relative_share"] = 1 / |CORE|                # 每日 CORE 等分
core["target_weight"]  = relative_share.clip(0.25) # 单只上限
  → 同 cluster 合计 > 0.40 ⇒ 按比例缩到 0.40
  → 同 cluster 合计 ∈ tech_clusters 且 > 0.65 ⇒ 只缩科技部分到 0.65
```

由此得到三条**结构性事实**：

1. **只有 `CORE` 拿到非零权重**；`CHALLENGER` / `SATELLITE` / 其他角色权重**恒为 `0.0`**。
   ⇒ `|CORE| = 0` 的交易日，持仓**完全为空、100% 现金**。
2. `target_weight = min(1/|CORE|, 0.25)` ⇒ `|CORE| ∈ {1,2,3,4}` 时**必然**被单只上限截断；
   只有 `|CORE| = 5` 时 `0.20` 不触发上限。
3. **科技 `0.65` 上限在 OOS 内仅 137 天生效（10.0%）** ⇒ 在 OOS 这段科技主导行情里，
   真正长期主导的约束是 **单只 `0.25`** 与 **cluster `0.40`**，**不是**科技上限。

> **`CORE == 0` 的 28.78%（OOS）/ 35.73%（全窗）是本包发现的最重要机制事实**：
> 策略在约三成的交易日里**手持全现金**，在单边上涨段系统性缺席。这是 **H2** 的来源。
