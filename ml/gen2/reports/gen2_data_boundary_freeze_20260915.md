## 1. 三层证据模型（执行口径）

与任务书 §2 同构，此处给出**可执行**的判定：

| 层 | 数据 | 允许产出的结论 | 是否可作生产资格 |
|---|---|---|---|
| **M — POSTMORTEM** | 全部**已被观察**的段（B3 OOS、`2020` 段、`2018-04-03→2020-03-06` 薄池段） | 机制假设（机制陈述 + 可证伪判据） | ❌ 否（证据力 0） |
| **R — RESEARCH** | O2 新增的**未观察**研究宇宙 | 「机制在未观察数据上成立 / 不成立」 | ❌ 否 |
| **Q — QUALIFICATION** | 当前 31 只池的**未来新增**交易日（O1 前瞻） | 生产资格判定 | ✅ **唯一** |

**禁止流动**（违反即视为违规，见 §7）：

- M 层数据 **不得** 用于定阈值、选参数、挑窗口、选标的；
- R 层结论 **不得** 表述为「具备 / 接近生产资格」；
- 任何报告若其结论依赖 M 层数据，必须在标题与首段标注 `POSTMORTEM_NOT_FOR_CALIBRATION`。

## 2. 冻结 ②：资产纳入规则

### 2.1 适用范围

适用于 **Stage R 研究宇宙**（O2）。纳入决定必须**逐只留档**（§6 模板），
且必须在**见到任何收益数据之前**完成 —— 即 **pre-registration**。

### 2.2 纳入必要条件（全部 MUST 满足）

| 编号 | 条件 | 说明 |
|---|---|---|
| **M1** | 交易所挂牌的**场内 ETF** | 含跨境 QDII（与现有池一致：`513310` / `513180` / `159941` / `513500` 均为 QDII） |
| **M2** | 在目标 Development 起点前，具备 **≥ 250 个交易日**的连续可交易历史 | 暖机期 = **250 个交易日**（§2.4 已冻结）；暖机是为了让特征（trend / rs / breakout）具备最小样本 |
| **M3** | 逐日 `OHLCV + 成交额` 字段齐备，且为**单一数据源的全历史前复权序列** | 见 §3.2 的跨源拼接禁令 |
| **M4** | 区间内**无**「连续停牌 > 20 个交易日」的缺口 | 停牌上限 = **连续 20 个交易日**（§2.4 已冻结；恰好 20 日不触发排除） |
| **M5** | 区间内**最近 60 个交易日日均成交额 ≥ 3000 万元**（逐段取最差 60 日窗口，见 §2.4 ①） | 流动性下限 = **3000 万元**（§2.4 已冻结）；研究池门槛，**非**生产门槛 |
| **M6** | 可归入现有 `sector / cluster / asset_class` 体系 | 与 `universe_v1.candidate_map` **同构**，否则跨宇宙不可比 |
| **M7** | **纳入规则先于任何收益数据冻结** | 违反即整段研究作废 |

### 2.3 排除条件（任一命中即 MUST NOT 纳入）

| 编号 | 排除 |
|---|---|
| **X1** | 非场内可交易品种（场外 LOF、分级基金、货币/债券 ETF、商品期货联接等） |
| **X2** | 上市日**晚于**「目标 Development 起点 − 250 个交易日」（即无法提供 §2.4 的暖机期） |
| **X3** | 区间内发生**长期停牌 / 退市 / 清盘 / 合并 / 标的指数更换**，且无法取得可比序列 |
| **X4** | 无法取得**口径可比**的前复权序列 |
| **X5** | 标的的**任何已被观察段**被混入 Dev / Val / OOS —— 已被观察的部分必须显式剔除并在文档中声明 |
| **X6** | **只纳入「至今仍存续」的标的**（生存偏差）—— 见 §2.5，**必须**显式记录区间内已清盘/合并的标的 |

### 2.4 数值门槛（**已裁决 · 冻结**）

> 本节五项数值由用户 **2026-09-15** 裁决冻结（裁决第 1 项），此前状态为 `PENDING_RULING`。
> **适用边界（用户裁决原话口径）**：这些门槛**只用于 O2 研究宇宙的数据准入**，
> **不改变** `gen2-rule-v2.0.1` 的已接受失败基线，**也不构成**任何参数调优。
> ⇒ **禁止**用本节数值去重判 V2.0.1，或据此宣称任何经济资格。

| 门槛 | **冻结值** | 适用层级 | 核验口径 |
|---|---|---|---|
| **暖机期**（M2） | **250 个交易日** | 逐标的 | 目标 Development 起点前，须有 **≥ 250 个交易日**的连续可交易历史 |
| **停牌上限**（M4） | **连续 20 个交易日** | 逐标的 | 区间内**不得**出现「连续停牌 **> 20** 个交易日」的缺口；**20 日以内（含 20）可接受，21 日及以上即不满足** |
| **流动性下限**（M5） | **最近 60 个交易日日均成交额 ≥ 3000 万元** | 逐标的 × 逐段 | 见下方「① 流动性口径」 |
| **最小标的数** | **每段 ≥ 15 只** | **段级** | Dev / Val / OOS **各段分别** ≥ 15 只 |
| **sector 覆盖** | **≥ 6 个**（现有 8 个 cluster 中） | **段级** | Dev / Val / OOS **各段分别** ≥ 6 个 cluster |

**口径细节（消除歧义，避免实现者各自解读）**：

1. **① 流动性口径 = 滚动 60 个交易日窗口的「最差」值**：逐标的、在每个段内逐日滚动 60 个交易日窗口，
   计算窗口内日均成交额；**取该段内全部窗口的最小值**作为该标的在该段的流动性读数，
   判定 `min(窗口均值) ≥ 3000 万元`。取**最差窗口**（而非整段平均）是有意的**保守**选择 ——
   整段平均会被个别高成交日拉高，从而放行一段内实际不可交易的日子。
   *若原意是「整段日均」或「段末最近 60 日」，请指出；按 §8 变更流程修正，不就地改。*
2. **② 停牌上限为严格不等式**：判定条件是「连续停牌 **> 20**」⇒ 恰好 20 日**不**触发排除。
3. **③ 段级门槛不达标时不得凑数**：最小标的数 / sector 覆盖不达标 ⇒ **该段不可用于其对应角色**，
   必须回到 **P1 重划分割**；**禁止**为了凑够 15 只或 6 个 cluster 而放宽 §2.2/§2.3 的逐标的准入条件。
4. **④ 门槛不得因结果不理想而调整**：五项一经冻结即长期有效；确需变更须走
   「新 revision + 用户二元批准 + §8 留痕」，**不得**以「临时实验」为名绕过。
5. **⑤ 门槛的用途**：仅用于**准入筛选**与**段级充分性判定**；**不得**作为策略参数、
   **不得**进入任何评分或信号构造。

### 2.5 生存偏差专项（审计最易失守的一项）

**必须产出**：目标区间内**曾存在但已清盘 / 合并 / 转型**的 ETF 清单，逐只记录
`代码 / 存续区间 / 终止原因 / 是否纳入及理由`。

- 若**无法**取得该清单 ⇒ 必须在该段的所有报告首段声明
  「**本段存在未量化的生存偏差**」，且该段的结论**只能用于机制否证，不得用于资格判定**。
- **禁止**用「只保留至今存续的标的」的池子做任何「选池能力」类结论 —— 那会系统性高估。

### 2.6 段级充分性门槛（**硬门**）

逐标的准入（§2.2 / §2.3）通过后，还须**逐段**核验充分性。任一不达标 ⇒ **该段不得进入其对应角色**：

| 段 | 最小标的数 | sector 覆盖 | 不达标时的处置 |
|---|---|---|---|
| **Development** | ≥ **15** | ≥ **6** / 8 个 cluster | 回 P1 重划分割（**不得**放宽逐标的条件凑数） |
| **Validation** | ≥ **15** | ≥ **6** / 8 个 cluster | 同上；若重划后仍不足 ⇒ 该假设**停在 R 层** |
| **Frozen OOS** | ≥ **15** | ≥ **6** / 8 个 cluster | 同上；**禁止**缩小 OOS 以求达标（会引入窗口选择） |

- **口径**：标的数 = 该段**每个交易日历日**都满足 §2.2 的标的总数，取**最小值**（不是并集）；
  sector 覆盖同理取段内**最小值**。
- **顺序约束**：段级充分性必须在 **pre-registration（§2.2 M7）之前**核验完毕 ——
  即先确认三段都够料，再冻结纳入规则；否则会出现「为了让 OOS 达标而回头改纳入条件」。

## 3. 冻结 ③：复权与费用口径（不 fork）

### 3.1 唯一权威

| 项 | 唯一权威 |
|---|---|
| 账本口径 | `ml/gen2/backtest/ledger.py` → `LEDGER_CONTRACT` |
| 费用实现 | `ml/gen2/backtest/costs.py` |
| 资产主数据 | `ml/gen2/universe/etf_master.csv` | 
| 宇宙定义 | `ml/gen2/universe/universe_v1.json` |

`LEDGER_CONTRACT` 逐字段（**不得改写**）：

```json
{
  "execution_lag_default": 1,
  "turnover": "one_way_stock_legs",
  "cost": "turnover * cost_bps/10000",
  "initial_state": "all_cash",
  "initial_equity": 1.0,
  "terminal": "mark_to_market_no_liquidation",
  "conservation": "Σtarget + cash == 1 and cash >= 0 and equity_t == equity_{t-1}*(1+net_t)",
  "calendar": "caller-supplied shared calendar",
  "missing_quote": "explicit missing_quotes column, never treated as 0 return"
}
```

关键语义（**不得 fork**）：

- **T+1 执行**（`execution_lag_default = 1`，signal-date API）：t 日执行的是 `prev(t)` 的目标权重；
- **换手 = 单边成交名义额** `Σ_证券 |target_c − pre_trade_c|`；**现金腿不计费**
  （现金↔证券是同一笔成交，用 `Σ_全部腿|Δ|` 会翻倍）；
- **期初全现金**、`initial_equity = 1.0`；**末日 mark-to-market、不强制平仓**；
- **资金守恒逐日必须成立**（`conservation_error` 必须为 0）；
- **缺行情不得当 0 收益**（必须走 `missing_quotes` 显式列）。

### 3.2 复权口径（本轮取数的**最高风险点**）

**现行口径**（`ml/gen2/config/gen2.yaml` / `data/schema.py`）：

```yaml
source: local_csv_qfq
adj_policy: adj_close_equals_close_for_qfq_v1     # 当前本地 qfq 源 adj_close = close
```

- `data_version = daily-qfq-v1`（`ml/gen2/features/build_features.py`）；
  `DATASET_MANIFEST_V1.json` 记 `source = local_csv_qfq`、`adjustment = qfq`。
- schema **保留** `adj_close` 字段以备将来切换数据源 → **不得**破坏该字段语义。

⚠️ **三条硬禁令（新增取数必须遵守）**：

1. **禁止跨源拼接**：**同一标的**不得把「腾讯 qfq」与「东财 qfq」两段**未校准**的序列直接拼接。
   前复权的**基准日不同** ⇒ 接缝处会出现**虚假跳变 / 缺口**，会直接变成假收益。
   **做法**：整段由**单一源重取**；若因数据可得性必须拼接，须在**文档化的锚点日**做校准，
   把**校准因子写入 manifest**，并在报告中显式声明。
2. **禁止依赖 `open` 构造日内收益**：前复权下 `open` 不可靠。
   既有先例：`ml/gen2/backtest/rotation_backtest.py` 中 `ret_intraday` 方案**因 `open` 失真被弃用**。
3. **禁止原地覆盖 `daily-qfq-v1`**：新数据必须声明**新的** `data_version`（命名由 M1 裁决，
   候选 `daily-qfq-v2`），旧 version 必须保持可复现（其内容摘要已入既有 manifest）。

### 3.3 费用档与验收

- 成本档：**0 / 5 / 10 / 20 bps**，**主判据 = 10 bps**（沿用 B1/B3）。
- **验收必须复用既有实现**（`ledger` / `costs`），**不得复制公式**到新模块。
- **机器化要求**：新工作的口径正确性，必须用「**新实现重算既有窗口的读数 == 既有已接受报告
  逐位**」来证明（沿用 B1/B3 的 H5c 做法：B3 曾以 **140 单元格 / 0 失配**证明同口径）。

## 4. 冻结 ④：访问顺序（Access Order）

**顺序即契约**。每个阶段只允许读它该读的东西；**越界即视为污染**（§7）。

| 序 | 阶段 | **允许读** | **禁止读** | 可重复？ |
|---|---|---|---|---|
| **P0** | 取数与审计 | 行情 `OHLCV`、成交额、上市日、停牌记录等**元数据** | 评分、持仓、净值、收益、任何指标 | ✅ 可重复 |
| **P1** | 冻结分割 | 仅元数据（用于确定日期边界） | 同上 | — |
| **P2** | **Development** | **Dev 段**行情 + 评分 | Val 段、OOS 段 | ✅ 可重复（在 Dev 内迭代） |
| **P3** | **Validation** | **Val 段** | OOS 段 | ⚠️ **每个假设仅一次** |
| **P4** | 封存 | 仅 **OOS 段的日期范围**（用于生成哈希） | OOS 段的**任何数值** | — |
| **P5** | **OOS（一次性）** | **OOS 段** | — | ❌ **仅一次** |
| **P6** | **O1 前瞻资格** | 当前 31 只池的**未来新增**数据 | — | 由**时间**自然保护 |

**四条铁律**：

1. **P3 的 Val 是「一次性」的**：每个假设只允许一次 Val 读取。反复读 Val 就等于把它变成
   第二个 OOS —— 这是实践中**最常见的自欺方式**。
2. **P5 的 OOS 只读一次**：读取即封档（§5.3）。
3. **顺序不可跳**：不允许「先看一眼 Val/OOS 再决定 Dev 怎么做」。
4. **任何**工具/脚本若会同时加载两段（如 Dev + Val），必须**显式**声明并留痕；
   默认实现必须**按 mask 截断**（§5.2）。

## 5. 冻结 ⑤：未观察 OOS 保留规则

### 5.1 封存对象

OOS 分割一经冻结，必须写入 manifest：

```json
"holdout": {
  "universe":      "<研究宇宙 id>",
  "first_date":    "YYYY-MM-DD",
  "last_date":     "YYYY-MM-DD",
  "calendar_sha256":     "<该段交易日历的 SHA256>",
  "loader_mask_sha256":  "<按 mask 截断逻辑的 SHA256>",
  "sealed_at":     "<ISO8601>",
  "opened_at":     null,
  "open_count":    0
}
```

### 5.2 物理隔离（不是口头承诺）

- P2 / P3 运行的 loader **必须按 mask 截断**：OOS 段的行情**不进入内存**；
- 截断逻辑的 SHA 必须入 `holdout.loader_mask_sha256`，使其**可被机器复核**；
- 断言：P2/P3 运行产出的任何中间产物中，**不得出现 OOS 段的任何日期**。

### 5.3 一次性令牌与读取即封档

- 读取 OOS 必须显式携带 `--open-holdout <token>`；令牌由**用户签发**（二元审批），**一次有效**；
- 写入 `opened_at` / `open_count`，**第二次读取直接拒绝**（fail-closed）；
- 无论结果如何，读取后**立即**归档为 `ACCEPTED` 或 `ACCEPTED_FAIL`
  （沿用 B1 / B3 的接受记录先例），**不得**停在「待定」。
- **失败同样归档**：失败结论是资产，不是负债（B3 即为此例）。

### 5.4 O1 前瞻段的等价纪律

- O1 段（Stage Q）**不需要** mask 截断，因为它由**时间本身**保护；
- 但 **O1 的判据必须先于结果冻结**（沿用 B3 协议做法：判据文档的 SHA 进 manifest）；
- **O1 不得用于参数搜索**：其唯一用途是**资格确认**（通过 / 不通过）。

### 5.5 六条禁令

1. ❌ 把任何**已被观察段**（§3.3 of 任务书）包装为新的 Frozen OOS；
   **特别是 `2020-03-10 → 2020-12-31`**（已落在 walk-forward 训练窗内）；
2. ❌ 看过 OOS 后再改阈值 / 窗口 / 标的池并重跑（**B3 的教训**）；
3. ❌ 在 OOS 上做任何形式的**选择**（挑成本档、挑区间、挑指标）；
4. ❌ 把 Val 段当 OOS 用（或反之）；
5. ❌ 用 R 层（研究宇宙）结论宣称生产资格；
6. ❌ 只报通过的结果、隐藏失败的尝试（**必须**登记全部假设，含被否证的）。

## 6. 冻结 ①：数据边界审计模板（可填写）

> 用途：M1 逐只留档。**未填完不得进入 M4。**
> 每个数值必须附**证据来源**（数据源名称 + 抓取日 + 可复核的引用）。

### 6.1 逐标的审计表（每标的一行）

## 7. 违规判定与处置

| 违规 | 判定 | 处置 |
|---|---|---|
| 用已被观察段定阈值 / 选参数 | **致命** | 该假设作废，登记为**无效尝试**（不得隐藏）；相关段永久禁用 |
| 看过 OOS 后改阈值重跑 | **致命** | 该 OOS 作废 ⇒ 需**新**的未观察段；已读取的事实**不得**用作任何选择的依据 |
| Val 被读多于一次 | **严重** | Val 降级为 Dev（不再具备验证效力）；须另立新 Val |
| 跨源拼接未校准 | **严重** | 该段读数作废，须整段单源重取 |
| 只纳入存续标的且未声明 | **严重** | 「选池能力」类结论一律作废 |
| 未做 P0/P1 冻结即看收益 | **致命** | 整段研究作废 |
| 为凑够段级门槛（§2.6）而放宽逐标的准入条件 | **严重** | 该段作废，须回 P1 重划；纳入规则须重新 pre-registration |
| 用 §2.4 门槛重判 V2.0.1，或据此宣称经济资格 | **严重** | 该结论作废；V2.0.1 归档状态不变（`ACCEPTED_FAIL`） |
| 新增参数 > 2 个 | **按停止条件处理** | 判定过拟合风险过高，登记否证 |

**原则**：**失败与违规都留痕，不得静默删除**。这一点沿用 B3 的做法 ——
失败结论同样出报告、同样归档、同样接受（`ACCEPTED_FAIL`）。
