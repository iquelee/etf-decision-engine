## 2. F4 缺陷现状（精确定位）

`ml/gen2/portfolio/portfolio_builder.py::build_portfolio_candidates` 与研究路径**各算一套权重**：

```python
def build_portfolio_candidates(roles: pd.DataFrame) -> pd.DataFrame:
    out = roles.copy()
    out["priority"] = out["rank"].astype(int)          # ← B2 违规：legacy rank
    out["target_weight"] = 0.0
    out.loc[out["role"] == "CORE", "target_weight"] = ...rdiv(1.0)   # ← B1 违规：1/n 等权
    return out.sort_values(["trade_date", "priority"])...
```

而权威路径 `ml/gen2/baseline/rule_v2_ab.py::build_v2_roles` 已在角色层算出**受约束的**权重：

- 单只上限 `max_single_weight`（0.25）
- cluster 上限 `max_cluster_weight`（0.40）
- 广义科技跨 cluster 上限 `max_tech_weight`（0.65，`tech_clusters=[tech_hardware, software_ai]`）

后果：研究基线（归因 / 敏感性 / rotation）与 `run_v2_backtest`（含上限 + 防守腿）**不是同一组合口径**，
经济指标不可比。同时研究组合**没有现金腿、没有防守腿**（B3 违规）。

夹具设计要点（避免自证）：
- 权威权重刻意取**非等权** `0.25 / 0.15 / 0.10` —— 等权 `1/3 ≈ 0.3333` 与三者都不同，
  任何「重置为等权」的实现都必然被抓住；
- 注入 score 刻意与 legacy rank **顺序相反**（515880 分数最高但 rank=3），
  任何「仍读 rank」的实现都必然被抓住；
- **B5 同分用例**：刻意让两只 score 相等（如 `159915` 与 `HEDGE` 同为 40），
  断言 priority 按 `code` 升序稳定裁决 —— 任何依赖输入行序的实现在**行序打乱后**必然翻转；
- **B6 归属用例**：断言腿行的 `sleeve == 'GEN2_CANDIDATE'`，且账本中**不存在**任何把
  sleeve 权重写进 `final_target` 字段的路径（静态守卫 + 运行时断言）；
- 两个静态守卫直接读源码断言 `out["rank"]` / `rdiv(1.0)` 不复存在。

## 4. 实施步骤（文件级）

### Step 1 · 统一构建器（B1 / B2 / B3 / B4）

重写 `ml/gen2/portfolio/portfolio_builder.py`：

1. 新增 `PortfolioBuildError`（缺失显式输入一律抛错，禁止静默 fallback）。
2. `build_portfolio_candidates(roles, *, priority, portfolio_config=None, features=None,
   defense_cfg=None, cash_code='CASH', apply_defense=False)`：
   - **B2**：`priority` 必填，形如 `{trade_date: {code: score}}`（显式注入）。
     缺 → `PortfolioBuildError`；**绝不读 `roles["rank"]`**。
   - **B1 / B4**：`target_weight` 直接沿用 `roles["target_weight"]`（来自 `build_v2_roles` 的权威值），
     只做 `> 0` 与上限复核断言（越界即抛错，而不是悄悄缩）；
     **删除全部 1/n 等权逻辑**。
   - **B3**：新增现金腿（`code=CASH_CODE`，权重 `1 - 持仓合计`，逐日）；
     可选 `apply_defense=True` 时调用 `gen2.portfolio.defense_gate.apply_regime_defense`，
     产生 hedge 腿 + `defense_state` 列。
3. `build_cluster_exposure` 语义不变（继续读 `target_weight`），但此时读到的已是权威权重。

### Step 2 · 调用方改造（4 处）

统一改为「从角色层已注入的 selection score 显式构造 priority」：

```python
priority = {d: dict(zip(g["code"], g["alpha_score_v2"])) for d, g in roles.groupby("trade_date")}
candidates = build_portfolio_candidates(roles, priority=priority, portfolio_config=pcfg, ...)
```

`alpha_score_v2` 即 WP-G2-05（F1）确认的**显式注入 selection score**，
因此这条改造同时满足「priority 来自注入 score」与「单一真相源」。
