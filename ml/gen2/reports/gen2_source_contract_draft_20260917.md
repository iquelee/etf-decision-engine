## 2. 来源资格条款（`EC-*`）

每条格式：**要求 → 判据（怎么算通过）→ 证据形式（留什么）→ fail-closed 行为（不通过怎么办）**。

### EC-01 单一来源整段可得性

- **要求**：目标区间的日线序列必须能**从同一来源一次取全**。
- **判据**：同一次抓取的 payload 覆盖完整区间；**不得**由两个来源各取一段后拼接。
- **证据形式**：payload 落盘 + `payload_sha256` + 首末交易日 + 来源标识 + 抓取时刻。
- **fail-closed**：无法一次取全 ⇒ 记 `FAIL`，**禁止拼接凑齐**。
- **依据**：freeze §3 硬禁令①（禁止跨源拼接未校准的前复权序列；两源复权基准日不同 ⇒ 接缝处假跳变
  会变成假收益）。此禁令在 M1-A 审计中已有**实证**（同区间两源读数出现非恒定偏离，价格比为非恒定值）。

### EC-02 复权口径必须可机器判定

- **要求**：来源必须能同时给出**复权序列**与**未复权序列**，使复权变换类型可被**机械判定**。
- **判据（沿用 M1-A 已跑通的方法）**：对同源 `fqt=1` vs `fqt=0` 做变换判定 ——
  - **A 比例式**：`qfq = raw × k` 且 `k` 分段常数；
  - **B 减法式**：`raw − qfq` 分段常数；
  - **C 未定**：两者皆不成立。
- **证据形式**：变化点数量、是否出现**负前复权价**、失真天数、判定结果 A/B/C。
- **fail-closed（B / C 的处置已于 2026-09-17 裁定，见 §9 U-02 / U-03）**：
  - 判定为 **B（减法式）**的标的 ⇒ **不得**进入正式经济读数（排除出正式收益 / 价格序列 / 回测输入）；
    允许保留为**机制研究 / 错误诊断 / 复权机制否证样本**。
    ⛔ **不再逐只「看情况放行」** —— 统一规则优先于个案特批。
  - 判定为 **C（未定）**的标的 ⇒ `ECONOMIC_USE: PROHIBITED` + `MECHANISM_REFERENCE: ALLOWED`；
    在复权机制被明确识别以前，**不做**收益 / 趋势 / 回测 / 资格判断。
- **依据**：M1-A 审计已建立该三分类判据，并把「有多少天异常」升级为「异常为什么发生」。

### EC-03 复权基准日必须与 payload 同时记录

- **要求**：来源的复权基准（通常是序列最后一个交易日）**必须显式记录**在资格记录里。
- **判据**：同一 URL 在不同抓取日返回**不同字节**时，必须能解释为基准日漂移，而非数据修订。
- **证据形式**：`generated_on`（抓取日）+ `payload_sha256` + 基准日。
- **fail-closed**：**`payload_sha256` 只在 `generated_on` 当日有效** ⇒ 跨抓取日引用同一 `payload_sha256`
  即为无效引用；跨源/跨日拼接一律拒绝。
- **依据**：M1-A 实测结论（复权基准动态漂移）；Stage A 事故封存 §3 同口径。

### EC-04 交易日历

- **要求**：交易日历必须独立可得，并与来源自身的行情序列**自洽**。
- **判据**：① 日历覆盖区间 ⊇ 目标区间；② 行情序列的交易日 ⊆ 日历；③ 与**独立第二来源**交叉核对，
  差异必须为 **0**（或逐条解释并留痕）。
- **证据形式**：日历 payload + `payload_sha256` + 首末交易日 + 交叉核对结果与差异清单。
- **fail-closed**：日历不可得或差异无法解释 ⇒ 该来源**整个作废**（因为 T+1 执行与停牌判定都依赖它）。
- **依据**：freeze §3（`execution_lag_default = 1` 的 T+1 口径依赖日历）；Stage A 中日历请求本身即为
  **预算第 1 次**请求（日历是关键路径的起点）。

### EC-05 字段完备性

- **要求**：来源必须提供下列字段，且**量纲/单位可确认**。

| 字段 | 是否必需 | 用途 | 备注 |
|---|---|---|---|
| 交易日期 | **必需** | 对齐日历、T+1 | 必须可解析为日期 |
| 开盘价 | 可选 | —— | ⚠ freeze §3 硬禁令②：**禁止依赖 `open` 构造日内收益**（已有因 `open` 失真被弃用的先例） |
| 最高 / 最低价 | 可选 | —— | 研究用途，非账本必需 |
| **收盘价** | **必需** | 账本 mark-to-market、收益计算 | 缺口处理见 EC-06 |
| 成交量 | **必需** | 流动性判据的辅助 | 单位须确认（股 / 手） |
| **成交额** | **必需** | freeze §2.4 流动性门槛（60 日日均 ≥ 3000 万元） | ⚠ 既有腾讯池 `amount` **整列为空**，这是必须补上的字段 |
| 涨跌幅 / 换手率 | 可选 | 审计交叉核对 | —— |

- **证据形式**：字段清单 + 样本值 + 单位声明 + 缺失率。
- **fail-closed**：`收盘价` 或 `成交额` 缺失 ⇒ 该来源**不能**用于 O2 逐标的准入判定。

### EC-06 覆盖能力（数值一律引用 freeze §2.4 / §2.6，不得新创）

- **要求**：来源须支撑以下**段级**（不是单段）充分性：

| 维度 | 门槛（引用 freeze） | 说明 |
|---|---|---|
| 暖机 | **250 个交易日** | 每段之前须留足 |
| 停牌 | 连续 **> 20 个交易日**才排除 | 严格大于 |
| 流动性 | 最近 **60 个交易日日均成交额 ≥ 3000 万元** | 取滚动窗口的**最差**值（保守口径） |
| 最小标的数 | **每段 ≥ 15 只** | 逐段核验，非并集 |
| cluster 覆盖 | **8 个 cluster 中 ≥ 6 个** | 分母定义见 `cluster_taxonomy_v1.json` |
| 缺行情处理 | **不得当 0 收益** | freeze §3 |
| 与已被观察段重叠 | **必须为空** | freeze §2.2 X5 |

- **证据形式**：逐段核验表（段 / 标的数 / cluster 数 / 最差 60 日成交额 / 覆盖率）+ 未达标项的处置记录。
- **fail-closed**：逐段任一维度不达标 ⇒ **回 P1 重划或降层**，**禁止放宽逐标的准入凑数**（freeze §2.6）。

- ⚠ **覆盖天花板属事实性约束（`U-04` 最终裁决，2026-09-17）**：若某方向 / cluster 在目标上市截止日前
  **结构性不存在**可交易标的（市场上没有对应主题的可交易 ETF），该情况记为 **`STRUCTURAL_NO_INSTRUMENT`**，
  属**事实记录**，**不是**来源能力缺陷。
  **裁决口径（唯一有效；2026-09-18 措辞收紧，裁决内容未变）**：
  - **覆盖率分母不扣除**；
  - 冻结的 **`≥ 6 of 8`**（8 个 cluster）分母**不得因 `STRUCTURAL_NO_INSTRUMENT`
    或任何结构性不可得方向而缩减**；
  - `STRUCTURAL_NO_INSTRUMENT` **仅作事实记录**，**不得用于准入结论**
    （可以登记、可以披露，但不构成覆盖率不达标的豁免或判据）；
  - 覆盖不足时的处置仍是「**接受不达标并如实披露**」，**不得**通过缩小分母使其达标，
    **也不得**静默删除该方向。
- ⚠ **与 freeze §2.6 的边界（继续有效）**：freeze §2.6 的段级硬门分母是**固定的 8 个 cluster**，
  且 §2.4 数值已冻结、变更须走 freeze §8「新 revision + 用户二元批准 + 留痕」。
  ⛔ **不得借 WP-G2-08 静默修改冻结件**；若未来要改 freeze 本身的 cluster denominator，
  **必须另立 `freeze-change package`**。本轮**未触碰 freeze**。

### EC-07 许可与再分发

- **要求**：来源的使用条款必须**书面可查**，且允许本项目的研究用途。
- **判据**：三问必须**都能回答**，且答案是「是」或「已声明为未知并承担风险」——
  ① 是否允许**程序化访问**（含访问频率约定）？
  ② 是否允许**本地缓存与留档**（本项目要求原始响应落盘）？
  ③ 是否允许**在内部报告中引用/再分发**派生结果？
- **证据形式**：条款出处（URL / 文档名）+ 三问逐条答案 + 记录日期。
- **fail-closed**：**未确认即视为 `OPEN`** —— 允许**内部研究**使用，但
  **禁止**对外发布原始 payload、**禁止**把数据集本身作为交付物分发。
- ⚠ **不得默认「公开可得 = 可再分发」**。许可状态不明确的来源，其资格记录中
  `license_status` 一律写 **`LICENSE_STATUS: OPEN`**（U-01 于 2026-09-17 裁定），**不得**写 `PASS`；
  `OPEN` 状态下的**允许 / 禁止清单与传播边界**见 §7（U-01 / U-06 裁定）。

### EC-08 可复现性

- **要求**：任何一次取数都必须能被**第三方在不问作者的前提下复算**。
- **判据**：下列四项齐备：
  1. **请求构造可机械重建**：URL / 参数全部由**代码常量**生成（标的代码、复权参数、复权类型等），
     不得含人工拼写或随机成分；
  2. **缓存键确定性**：键只依赖请求 URL（本项目现行口径：`sha256(原始 URL)[:16].json`），
     不得依赖时间戳、本机路径或随机数；
  3. **payload 指纹**：每份 payload 记 `bytes` + `payload_sha256`（口径见 §3）+ `generated_on`；
  4. **失败同样留痕**：失败必须写入进度记录，**不得静默删除**（freeze §7）。
- **证据形式**：复现命令 + 缓存键清单 + 指纹清单 + 进度记录。
- **fail-closed**：缺任一项 ⇒ 结果只能作**本地观察**，**不得**进入任何审计或资格文档。

## 3. 哈希口径（引用 sha256 时必须声明）

本项目存在**两套** sha256 口径，混用会产生看似矛盾但实为不同问题的结论：

| 口径 | 定义 | 用途 |
|---|---|---|
| **raw 字节 sha256** | 直接对文件字节求 sha256 | payload 指纹、差分论证 |
| **项目口径 sha256** | `sha256( utf8 解码 + CRLF→LF 归一化 )`（= `scripts/verify-immutable.js::sha256File`） | `bundle_sha256` / `lock_sha256` / `ROOT_ANCHORS` |

**强制要求**：任何文档引用 sha256 时**必须写明是哪一套**。例如同一文件可能 raw 与归一化值**完全不同**，
若只写「sha256 = …」会被后续读者当作同一对象比对，产生假冲突。

## 4. 复权契约（引用，不 fork）

- 复权类型判定：见 **EC-02**（A/B/C 三分类）；**B / C 的处置见 §9 U-02 / U-03 裁定**。
- **禁止**：跨源拼接未校准的前复权序列（EC-01）；依赖 `open` 构造日内收益（EC-05）；
  原地覆盖既有数据版本（须声明新 `data_version`）。
- **拼接（U-05 已于 2026-09-17 裁定）**：**正式资格数据继续禁止拼接**。
  原因：不同来源的**复权基准 / 公司行动处理 / 精度 / 时间戳**可能在接缝制造**虚假收益**。
  仅允许 `DIAGNOSTIC` / `MECHANISM_ONLY` 用途；**不得**进入正式历史序列、收益计算、回测或来源资格判定。
  未来若要开放拼接，**必须另立独立的 normalization / stitching protocol**，**不在 WP-G2-08 顺手放开**。

## 5. 日历契约

见 **EC-04**。要点：日历是**预算第 1 次请求**（关键路径起点）；日历不可得 ⇒ 来源整体作废。

## 6. 覆盖契约

见 **EC-06**。要点：**段级**核验，不是**并集**；缺行情不得当 0 收益；结构性不可得须与来源缺陷分开记。

## 7. 许可契约

见 **EC-07** 与 **§9 U-01 / U-06 裁定**。要点：

- 未确认即 `LICENSE_STATUS: OPEN`（**不是** `PASS`）。**可以登记，不等于可以正式使用。**
- `OPEN` 状态**允许**：记录来源 · 做技术验证 · 做内部诊断。
- `OPEN` 状态**禁止**：作为正式资格结论依据 · 进入正式经济读数 · 对外转发原始数据或实质性数据摘录。
- **传播边界（U-06）**：许可未明确时 **允许受限内部分析；禁止外部转发**。
  内部报告**只允许**派生结论 / 必要的汇总指标 / 非替代原数据价值的图示；
  **禁止**大段原始数据重现 · 数据包转发 · 对外分享来源实质内容。
- 许可条款补齐后**重新评估 / 重新裁定传播边界**。

## 8. 可复现性契约

见 **EC-08**。要点：请求可机械重建 + 缓存键确定性 + payload 指纹 + 失败留痕，四项缺一不可。
