## 2. `cluster_taxonomy_v1`（裁决 D）

### 2.1 问题：冻结文本里的「8」**没有任何出处**

`freeze §2.4 / §2.6` 与 `taskbook §0.9` 把门槛写成「**现有 8 个 cluster 中 ≥ 6 个**」。全仓库检索结论：

- 「8 个 cluster」**只**出现在上述两处（5 行），**无任何文件枚举其成员**；
- Rule V2 的冻结 bundle `GEN2_RULE_V2_BUNDLE.json` **根本不定义 cluster 成员** —— 它只定义
  `portfolio.tech_clusters = ["tech_hardware","software_ai"]` 与 `selection.max_core_per_cluster = 2`。

### 2.2 四套实测口径（互不相同）

| 口径 | 来源 | 基数 | 成员 |
|---|---|---|---|
| L2 实现 cluster | `ml/gen2/universe/clusters_v1.json` | **11** | tech_hardware, software_ai, growth_broad, healthcare, consumer, financial, defensive_dividend, cyclical_resources, overseas_equity, gold_commodity, broad_beta |
| `correlation_cluster` 列 | `ml/gen2/universe/etf_master.csv` | **11** | 同上（**与上者零分歧**） |
| 30 只 `eligible_codes` 实覆盖 | `universe_v1.json` | **10** | 11 去掉 `broad_beta` |
| `candidate_map`（仅 16 只新增） | `universe_v1.json` | **7** | software_ai, healthcare, consumer, defensive_dividend, financial, cyclical_resources, overseas_equity |

### 2.3 冻结的构造：两条独立路径同时得到 **8**

> **8 = 11 个 L2 cluster 去掉 3 个「非行业/主题」cluster**
> = `broad_beta`（基准宽基；`max_core_count=0`，且 `510300` 在 `excluded_from_core_competition`）
> + `growth_broad`（宽基成长，`sector=broad`）
> + `gold_commodity`（商品/对冲，`sector=commodity`）

等价校验（独立路径）：`etf_master.sector` 共 **10** 个取值，去掉非行业的 `broad` 与 `commodity` ⇒ **8**。

**冻结分母（8 个行业/主题 cluster）**：

`tech_hardware`（科技硬件）· `software_ai`（软件/AI）· `healthcare`（医药）·
`consumer`（消费）· `financial`（金融）· `defensive_dividend`（红利防御）·
`cyclical_resources`（周期资源）· `overseas_equity`（海外权益）

> ⚠ 这**不改变**冻结门槛的数值「≥6」。它只把**分母的定义**从「无从复算」补成「可复算」。
> 若裁决认为分母应为 9 / 10 / 11，`cluster_taxonomy_v1.coverage_denominator` 改两个字段即可，
> 其余结构不变。

### 2.4 一致性校验：**零分歧**

| 校验 | 结果 |
|---|---|
| `clusters_v1.json` 成员 vs `etf_master.correlation_cluster`（31 只） | **0 处分歧** |
| `keyword_rule_v1` 对既有 31 只池的分类 vs 文件权威 | **0 处不一致** |
| `cluster_taxonomy_v1` L2 层 cluster 数 | 11（= 文件权威） |

⇒ 关键词规则虽为派生，但在既有池上与权威逐只吻合，可安全用于**池外**候选的指派建议。

### 2.5 ⚠ 治理缺口（重要，需裁决）

Rule V2 的 `immutable_set` 是 **8 项**（bundle / JS 实现 / rule_v2_ab.py / portfolio_builder.py /
defense_gate.py / role_thresholds.py / selection_scores.py / regime.py）。
**`clusters_v1.json` 与 `universe_v1.json` 都不在其中** ⇒

> 在 bundle 字节不变、LOCK 不改的前提下，**改动 cluster 成员关系即可改变运行语义**
> （例如把某只标的从 `tech_hardware` 改到 `consumer`，可绕开 `max_cluster_weight = 0.40`
> 与 `max_tech_weight = 0.65` 的约束）。

这与已修补的 `role_thresholds.py` / `regime.py` 是**同一类旁路**。本包的处理是：
用 `cluster_taxonomy_v1` **冻结成员映射**（研究侧），但**不**擅自把 `clusters_v1.json` 纳入 LOCK ——
那属于「新 lock revision」，须用户批准。

### 3.5 附加发现（P1 必须先处理）

1. **O2 窗口被封在 `≤ 2018-04-02`**：观察段自 `2018-04-03` 起，
   故 O2 的 Dev/Val/**Frozen OOS 三段必须全部落在 2018-04-02 之前**（约 2005–2018，10 年 ~2400 交易日）。
   ⇒ O2 的 Frozen OOS 将**早于** B3 的 OOS，**属于不同市场制度（regime）**，
   结论跨制度外推性必须在报告里声明，不得当作 B3 的直接替代。
2. **同类重复暴露**：候选里存在大量同指数多产品（如 `中证500` 5 只、`证券` 4 只、`军工` 3 只、`创业板` 4 只）。
   O2 若不去重，会人为放大同一 beta 的权重。**建议**：P1 前加一条**「同一 L2 cluster 内按标的去重
   （同 underlying_index 只留流动性最优一只）」**的规则 —— 但**该规则须用户批准后才生效**，
   因它会改变 universe 构造方式。
3. **`512280`（`MSCIA股ETF景顺`）已于 2025-08-21 终止上市**（上交所公告，见 §4）
   —— 直接证明「用今天的 ETF 列表回溯历史」会漏掉已退市标的，即**生存偏差真实存在**。
