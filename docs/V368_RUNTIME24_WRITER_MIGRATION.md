## 写入面及现有防重的边界

| 阶段 | 已识别写入 | 为什么不能并跑新旧生产实例 |
|---|---|---|
| 抓取 | etf_daily、fetch_log、fundamental_series、market_env、global_quote | 双Lane就绪检查发生在写前；force可重抓，不是并发互斥 |
| 物化 | indicator_snapshot、etf_weekly | 同键upsert不阻止两次计算、状态观察及下游调用 |
| RDE | fundamental_config同步、fundamental_state、portfolio_position、候选/manifest/history/pointer、shadow_v3_log、runtime_status；LEGACY分支还有旧结果/组合写入 | 部分副作用先于pointer CAS，未发布run也可能已写状态 |
| 后台 | 风险/参数/持仓等直接修改，以及触发RDE/抓取 | 仅暂停timer不能排除后台和已发起的异步调用 |
| 实时抓取 | etf_daily.realtime及缺当日行时插入、fetch_log | 与日线共享集合；先保持原函数和时间表，迁移窗口需考虑输入更新 |

证据入口：fetchDailyData/index.js:104、278、424；materializeIndicators/index.js:71、143、192；runDecisionEngine/index.js:547、1126、1139、1417、1477、1509、1713；adminGateway/index.js:582、613、696、1000。以上位置同时在新鲜下载中核对，后续代码变化须重定位。

`db.upsert` 是查询后update/add，不是全链锁。RDE的engine run id含startedAt，同一业务请求重发可产生不同run；pipeline correlation用于关联，不能视为exactly-once凭据。现有单文档pointer CAS只保护正式数据集可见性，不替代上述所有副作用的执行互斥。

## 分批顺序与统一入口

1. **离线协议及封包验证**：实现并验证执行准入、排空和失败语义；在新鲜RDE包和精确依赖上做Node22/24实际入口回放，覆盖真实副作用和发布存储，不调用生产。此阶段不创建云资源。
2. **受控准入基座**：未来独立发布批次在旧、新RDE所有执行路径的最前面接入共同准入；必须早于`syncFundamentalConfigs`及任何业务写。新Node24候选默认禁止业务执行、零timer，不因“未绑路由”就认定其安全。需要云端写能力验证时，只使用明确列出的隔离验证集合和固定测试文档，另绑定授权；不能用生产集合验证写兼容。
3. **RDE单点切换**：保留调用方使用的`runDecisionEngine`函数名作为稳定入口；旧名后续成为转发门面，实际实现选择由受控owner决定。切换前两个实现均须具备互斥准入，旧内联实例排空；不要逐个调用方直接改到新函数后容许旧实现继续执行。Node16门面此时仍保留，不能宣称写链已完全摆脱Node16。
4. **物化再迁移**：审核四项common差异、独立回放后，仍经相同RDE入口调用；保留原08:00唯一timer所在入口，独立切换物化实现。若将来移动timer，须另给出停旧/核验/开新的精确顺序及失败回退，不能两个timer重叠。
5. **日线抓取再迁移**：逐项解释40项common差异，验证两Lane、定稿/force、宏观写入和下游事件，再切换唯一22:00入口。实时抓取及新闻/提取、Gen-1等另批处理。

稳定门面应保持`from`、pipeline身份、事件字段及下游返回契约；调用超时不代表下游停止。门面不得自动重试、超时后回落旧实现或同时扇出。嵌套调用的平台时限、返回包装和错误语义须实包验证；不能单凭本地mock认定120秒门面与120秒下游兼容。若平台约束无法满足，则改用全调用方切换方案并重新列范围，不能临场扩大部署。

## 拟实现的准入与排空协议

以下设计已由独立离线原型验证；**尚未接入生产RDE、实现CloudBase准入适配器或取得Node24平台写证明**。控制集合名称、角色权限和部署包未封存。

- 控制记录按环境与生产RDE scope确定主键，携带`revision/owner/epoch/state/active_execution`。owner、状态及活动执行槽必须由同一记录的条件CAS协调，不能“先读开关再单独抢锁”而留下切换竞态。准入默认拒绝缺记录、未知owner、错epoch、读取/条件更新失败；force和后台调用不得绕过。
- 旧、新实际实现都必须在任何业务写前占有唯一执行槽，owner/epoch和执行token匹配才可进入。门面本身不重复持有同一槽以免嵌套死锁。串行准入与请求去重是两件事；重复请求应有稳定请求身份和明确回执，不能只用startedAt或同一交易日拒绝全部重算（夜间、盘前、人工参数变化可能合法）。
- `ACTIVE_OLD → DRAINING_OLD` 条件更新后拒绝新执行，已获准的旧执行完成并以token条件释放。只有活动槽为空且所有旧实现调用已证明终结，才能CAS切owner至`ACTIVE_NEW`。新旧owner不能同时开放。
- 失联、调用超时、失败释放和平台重试均进入HOLD/待核实；禁止按TTL到期自动接管。仅靠写前读epoch仍有检查与写入之间的竞态，不能称为可靠fencing。若无法证明旧执行已终结，保留HOLD，不切owner；后续需要支持抢占时，应另行实现平台可证明的逐写fencing。
- 第一次给未受控旧代码加准入尤其需要维护窗口：暂停已识别生产触发及后台写入口，处理已发起调用与队列重试，核对日志终结后再装基座。更改函数包不保证旧热实例已停止。timer、后台和SDK调用方封闭证据缺一则不进入切换；不能只靠“没人操作”或等待120秒。

暂停或队列策略必须覆盖后台风险/参数/持仓等与RDE共享状态的修改；暂停页面按钮不足以证明服务端已关闭入口。实际控制实现及对用户的维护提示要在未来候选中审阅。本次不改后台生产行为。

## 自然验收与限定回退

选择避开08:00、22:00链路和盘中输入变动的维护窗口，并先核对当日真实执行。排空等待界限必须根据已部署完整调用链、平台投递/重试、各函数运行日志确定；本设计不给未经证明的固定分钟数。

切到新owner后首先只读确认运行时、源码/包、准入状态和唯一timer配置，再等待下一个自然run。分别验收夜间与盘前：COMPLETE、validation_passed、5+1交易日一致、promoted history/pointer/source/context一致、无重复执行副作用，原域API和历史回读一致。timer触发、函数exit0、无报错或pointer revision增长单项均不足以通过。

异常时先关闭新准入、排空/证明新执行终结，再把owner恢复为旧实现；保留当前有效正式pointer及已发布历史，不删新run、不回写市场/持仓/历史数据、不把pointer退到旧revision。若新执行状态未知，进入HOLD并报告；不自动启动旧实现掩盖未知写入。回退后同样等待自然运行验收，记录是否真正执行过回退；包准备不算实际演练。

## 离线原型与实际包回放结果

`release/writer-admission.js` 不被任何生产函数引用。它要求同一控制记录CAS协调准入/排空/owner/epoch与唯一执行槽；缺失记录不自动初始化，无重试、TTL接管或异常finally释放。初始化为HOLD，执行身份由调用方显式提供，不用交易日或startedAt猜测去重键。完成回执保留跨owner去重；容量128条耗尽即拒绝，尚无可发布的长期回执归档方案，不能用于持续生产。

`scripts/lib/writer-admission-memory-store.js` 只模拟单记录原子CAS。激活所需proof引用和三个布尔值只是外部证据接口，原型不验证其真实性，也不解决权限、队列重试及旧热实例排空。平台能力仍须另证。

新增两个自动发现的Node测试覆盖20路同快照竞争、读与CAS之间排空、重复/合法同日请求、旧epoch/错环境、force不越权、超时/失联、确认丢失、释放失败、容量上限。未知执行保留槽；不因时间经过或operator提交空泛切换请求就接管。`outcome:COMPLETE`仅表示handler正常终结并确认释放，原样保留业务`ok:false`，不等于正式发布成功。异常/确认不明保留UNKNOWN且不自动再运行。

完整入口回放使用`scripts/lib/rde-offline-harness.js`：加载整个未修改的index.js、真实common/db.js、决策、交易日历及发布存储适配器；仅在SDK数据库边界使用内存集合。合成行情/持仓、固定时钟、无真实凭据，禁止网络/函数调用及不允许的模块，文件接口只读。该VM供已审核代码回放使用，不作为不可信代码安全沙箱。SDK2.11.0的真实云端写入没有在本轮执行。
