## 提交与重试

旧前端 `api/request.js` 与新前端 `rewrite/api.js` 的全部后台 POST 共用 `utils/admin-operations.js`。提交前取得浏览器同源 Web Lock，并持久保存 UUIDv4、端点、时间和状态；一个同源最多一笔未结算人工操作。同页同载荷双击共享原 Promise，不再发第二次请求；另一页竞争立即拒绝，不排队变成新操作。缺安全随机 UUID、Web Locks 或可读写存储时，写请求拒绝，不静默换成随机请求 ID 或无锁调用。读请求保持原样。

操作 ID 放在 `X-Writer-Operation-Id`。同页明确重试沿用同一 ID 和最初载荷快照，JSON 对象键顺序不影响判定；改动载荷或换端点会被阻止，反复点击也不能替换原快照。网络异常、超时、非法 JSON、HTTP 错误、确认身份不匹配或缺失都保留待核对状态。没有自动网络重试、回退目标或新 ID 重提。旧请求客户端的后台写等待上限与新客户端一样为 20 秒；它只是客户端等待期限，不缩短 60 秒业务预算，也不能据此推断服务端已停止。

持久记录只含上述元数据，不含 body、密码、token 或其指纹。原 body 快照仅在内存中；刷新后无法证明待提交载荷相同，故必须先核对，不能猜测并重发。多页通过 storage 事件同步提示，Web Lock 在真正发送及确认处理期间持有。

## 明确的 HTTP 确认协议

后台根入口新增两个顶层字段，原 `code/data/message` 及业务内容保持：`operation_id`、`writer_outcome`。COMPLETE 表示原 handler 已返回完整结果，**不表示业务成功**；业务失败也保留其原 code/data/message。DENIED 用于准入前维护/会话拒绝；ALREADY_COMPLETE 表示原操作已结束但没有缓存其完整业务返回；UNKNOWN 保持待核对。只读响应不添加字段。

客户端只接受匹配本操作 ID、合法原业务 envelope 的确认。COMPLETE 后才能结算并交回原业务响应；首次明确 DENIED 可结束本次未执行提交。**一旦结果曾不明，后来的 DENIED 不能证明先前没执行，仍保留原 ID。**ALREADY_COMPLETE 不伪造原成功结果，必须核对后结束。无操作确认的旧后台即使返回 code0，也不会被当作本协议已完成。这是必要的兼容边界，前后台必须一起切换。

该元数据是有意的 HTTP 响应扩展：完整后台对拍只剥离并单独严格核验这两个字段，其余所有返回字段、业务写入顺序和全部集合值继续与原入口相等；未删除任意业务字段来迁就测试。

## 页面核对

新旧两入口均显示同一个核对提示，跨路由/刷新保留。浏览器检查发现新前端部分后台页仍为占位页，因此“刷新查看结果”打开对应的完整 Legacy 记录页，而不是停在无法核对的占位页。核对后还需勾选确认，才能结束本地操作记录；结束不调用后台、不取消业务、不清回执、不解除 HOLD。仍不确定时应保持待核对，不能把新操作当作原请求的重试。

登录、退出和改密也纳入同一提交协议，密码不持久保存；相应核对入口回到登录页。新前端原受治理 RouterView render 根保持不变，核对提示作为独立 Vue 挂载点随全站存在，不使用 runtime-only 不支持的字符串模板。
