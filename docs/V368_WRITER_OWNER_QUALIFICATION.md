# 生产候选的子引擎归属资格

状态：离线修复，未部署，不能据此启用生产写链。

物化和后台 Node24 候选的子调用会读取 `production/runDecisionEngine` 控制记录。此前路由同时列出旧 `runDecisionEngine` 与新 `runDecisionEngineNode24`；若控制记录仍为 old/ACTIVE，签名请求可能发到尚未接入签名准入的旧业务入口。旧入口可能先写数据，再因响应不含新协议回执而让父请求进入 HOLD；响应核验发生在调用之后，挡不住这次旧业务执行。

生产 bootstrap 现在将这两条子路由的资格固定为 `allowedOwners: ['new']`。直接调用器在签名和传输前检查控制归属；old/ACTIVE 返回 `WRITER_ADMISSION_DENIED / OWNER_NOT_QUALIFIED`，不调用旧入口，也不改动子控制记录。父调用沿用现有失败锁存，使父 journal 保持 UNKNOWN/HOLD/占用，不能假称该次业务已完成。此行为不证明父业务在尝试子调用之前没有写入；切换时仍必须先满足全部子节点的资格和闭包条件。

资格数组在调用器和 invocation worker 创建时复制、校验并冻结，后续修改配置对象不能扩大允许归属。通用调用器仍支持显式包装过的 old/new worker 模型；生产 bootstrap 不取得旧入口资格，也没有 fallback。没有修改原生产函数、生产状态、密钥、IAM、Timer或数据库。
