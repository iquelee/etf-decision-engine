## 2. 主决策链：最终建议 100% 来自 runDecisionEngine（V3.6.1 Safety Core）

结论一句话：**线上没有第二引擎能改最终仓位。ML / Gen-1 / Gen-2 全部是影子观察，`execution` 永久关闭，人工执行。**

证据（`runDecisionEngine/index.js` 801–855 行）：

```
mlMeta = {
  enabled: mlShadowObserve,      // 观察开
  effective: false,              // 无生产写权限（即使误开 fast_path）
  fast_path_enabled: false,      // 强制 OFF
  ...
}
```

返回体顶层：`ml_effective: false`（冗余语义：生产决策不受 ML 影响）。

因此「后台显示 `ml_fast_path_enabled=true`」≠「ML 已进入最终 target」——那是 adminGateway 的**展示字段**，不是 runDecisionEngine 的**决策字段**。二者必须分开命名与分开验收（见 §4）。

## 3. common 副本分叉：三个变体，不是两个

对 5 个带决策逻辑的函数逐一比 SHA256，得到**三个** common 变体：

| 文件 | 主链版（runDecisionEngine / apiGateway / runGen2ShadowEod） | Gen1-advisory 版（runGen1ShadowEod） | admin-advisory 版（adminGateway） |
|---|---|---|---|
| `common/constants.js` | `772c3f01f3ea` | `c276c55594c8` | `c276c55594c8` |
| `common/schema.js` | `428e92f9dbc3` | `307e99865d96` | `ee53634fa2ef` |
| `common/utils/ml-shadow.js` | `562f3be68b25` | `8edf074d5097` | `7f56a38bbf2f` |
| `common/utils/decision-v3.js` | `94f1d9c9577a` | `677fd675cc48` | `677fd675cc48` |
| `common/utils/decision.js` | `0a05fe7f0d6c`（五处完全一致） | ← | ← |

补充：`runGen2ShadowEod` 的 `constants.js` 为 `a8013c1b8829`（在 `772c3f0` 基础上新增 `GEN2_SHADOW`/`GEN2_DAILY` 集合名），其余 common 与主链版完全一致。

**语义差异（已逐行 diff 确认）**：

| 维度 | 主链版（生产建议） | Gen1/advisory 版（runGen1ShadowEod + adminGateway） |
|---|---|---|
| `ml-shadow.effective` | 恒 `false` | `advisory && ml_advisory_enabled !== false` |
| `fast_path_enabled` | 恒 `false` | `advisory && ml_fast_path_enabled !== false` |
| `production_permission` | `BLOCKED` | `ADVISORY_ONLY` |
| `ui_phase` | `OBSERVE` | `ADVISORY_ACTIVE` |
| 输出额外字段 | 无 | `advisory_target_pct` / `baseline_target_pct` / `effective_stage` / `baseline_stage` / `rule_permission_*` / `category_coverage` 等 |
| permission 来源 | 只读 `rule_gate`/`permission` | 优先 `decision.ml_rule_permission`（Safety Core 复核） |

**结论**：advisory 版多出的字段只影响「人工可见主建议」的展示与归因，不影响 `final_target` 的计算来源（仍由 runDecisionEngine 的 V3.6.1 骨架产出）。但当前**没有任何地方**把 `advisory_target_pct` 注入 `final_target`——这正是报告 P1-3 所指「代码里已经有 Advisory，不能证明它已进入最终 target」。

## 4. Gen-1 / Gen-2 权限边界（冻结）

| 引擎 | 管什么 | 能写什么 | 不能写什么 |
|---|---|---|---|
| V3.6.1 Safety Core（runDecisionEngine） | 风险与仓位最终约束 | `decision_result` / `portfolio_snapshot` | — |
| Gen-1（runGen1ShadowEod） | 已定义模型域内的机会判断（Advisory 展示） | 只 `ml_shadow_signal` 观察行 | 不改 `final_target`、不自动执行 |
| Gen-2（runGen2ShadowEod） | 选池 / 角色 / 替换**提案** | 只 `gen2_shadow`（type=gen2_run/gen2_ranking/gen2_diag） | 不改仓位、不写 decision_result、不写 portfolio_* |
| 人 | 最终执行 | TRADE_LOG（后台手工） | — |

`gen2_shadow` / `gen2_daily` 集合定义**仅存在于 runGen2ShadowEod**；apiGateway 与 adminGateway 均无任何 Gen-2 消费代码（已 grep 确认）。即：**Gen-2 当前没有下游消费者**。

## 5. 单一规则 schema（跨语言契约骨架）

> 目标：Python（`ml/gen2`）与 JS（`runGen2ShadowEod`）逐日对照时，以下字段语义必须严格一致。分数允许约定数值误差，**角色与代码集合必须严格一致**。

| 字段 | 语义 | tie-break | 说明 |
|---|---|---|---|
| `code` | 标的代码 | — | — |
| `trade_date` | 信号日（自然交易日） | — | 唯一键 `(code, trade_date)` |
| `eligible` | 当日资格 | — | 逐日计算，不是「最新日资格筛出后重算全历史」 |
| `alpha_score_v2` | (Trend + RS + Breakout)/3 | — | 只对**可排名集合**做横截面，先固定集合再算 |
| `rank` / `rank_percentile` | 横截面排名 | 分数相等按 `code` 升序 | 确定性 |
| `trend_gate` | price > MA60 | — | NO_CORE 绝对硬门槛 |
| `role` | CORE/CHALLENGER/SATELLITE/RESERVE/HEDGE | — | 状态机最终输出 |
| `reason_codes` | 角色变化原因（`|` 拼接） | — | 逐条可审计 |
| `replacement` | 一对一替换对 | — | 每对验证净边际 + 持久性 + 组合约束 |
| `target_weight` | 候选权重（0–1） | — | 缩到单只/cluster/tech cap 内，剩余留现金 |
| `selection_share` | 池内相对份额 | — | 观察字段 |
| `candidate_weight` | 影子组合权重（0–1） | — | 观察字段 |
| `final_target_pct` | Safety Core 最终建议（0–100） | — | 仅 V3.6.1 产出 |

单位转换只发生一次；Gen-2 当前仅拥有 `selection_share` 与 `candidate_weight` 的观察权限。
